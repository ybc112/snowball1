# 雪球发射台合约机制说明

## 一、设计目标

雪球发射台需要同时支持普通部署、一键加池发射和 Mint 募集发射。

三种发行方式应尽量复用同一个雪球代币核心，保证交易税、平台税、持币分红、自动回流、交易燃烧、底池单边燃烧和开盘保护的行为一致。

代币合约不负责在构造过程中自行创建 Pair。Pair 应由 Factory 或 Mint Vault 创建，并把 Pair 地址配置给代币。

这样可以降低代币合约复杂度，也便于支持普通 PancakeSwap V2 池、Mint 募集完成后的池子以及未来其他交易池版本。

## 二、总体架构

系统建议由以下模块组成：

- SnowballFactory：接收用户参数、收取创建费、计算平台税和部署项目。
- SnowballTokenDeployer：负责 CREATE2 部署和靓号地址。
- SnowballToken：负责交易税、开盘保护、分红记账和底池燃烧。
- SnowballTaxProcessor：负责税费兑换、平台收入和项目资金分配。
- SnowballDividendDistributor：负责持币分红。
- SnowballMintVault：负责 Mint 募集、逐步加池、募集完成和退款。
- PancakeSwap Pair：保存代币和 WBNB 或其他交易对资产。

Token 不应在内部调用 PancakeSwap Factory 创建 Pair，而是接收外部已经确定的 Pair 地址。

## 三、发行模式

### 普通部署

普通部署只创建代币，不自动添加流动性。

代币供应量发送给项目方，项目方自行创建或选择 Pair、添加流动性并开启交易。

项目方完成 Pair 配置前，交易保持关闭。

普通部署适合希望自己控制加池时间、初始价格和 LP 处理方式的项目。

### 一键加池发射

Factory 部署代币后，使用用户提供的 BNB 和代币添加流动性。

获得的 LP 全部发送到黑洞地址，表示初始流动性永久锁定。

剩余代币发送给项目方。

Factory 完成 Pair 配置、LP 销毁和开盘后，把允许保留的管理权限交给项目方，或者按照用户选择直接放弃 owner。

### Mint 募集发射

Mint 用户支付 BNB并获得代币，每次 Mint 对应一部分代币和一部分流动性资金。

Mint Vault 可以逐步添加流动性，也可以在募集完成后一次性添加。

达到目标 Mint 数量后：

- Vault 确认 Pair。
- 将募集资金和预留代币加入流动性。
- 把 LP 发送到黑洞。
- 把剩余代币按规则处理。
- 启动交易。
- 放弃 Vault 管理权限。

如果募集失败，应根据规则允许用户退款并撤回尚未永久锁定的流动性。

## 四、Pair 机制

底池单边燃烧仍然必须知道 Pair 地址，但不需要由 Token 自己创建 Pair。

推荐流程是由 Factory 或 Vault 创建 Pair，再将 Pair 地址设置进 Token。

Token 只识别经过 Factory 确认的主 Pair。需要支持其他交易池时，由受控流程增加新的合法 Pair。

Pair 地址设置后应禁止随意更换，避免项目方把虚假地址设置为主池，影响税费和燃烧。

## 五、LP 黑洞与底池燃烧

LP 转黑洞和底池单边燃烧是两个独立机制。

LP 转黑洞代表对应流动性份额不能再被赎回，防止项目方撤池。

底池单边燃烧代表 Token 合约从 Pair 的本币余额中转出一部分到黑洞地址，然后调用 Pair 同步储备。

即使 LP 已经全部进入黑洞，底池里的本币仍然可以进行单边燃烧。

底池燃烧不会销毁 WBNB 一侧，只减少池内本币储备，因此会改变池内资产比例和价格。

## 六、底池单边燃烧规则

底池燃烧建议采用公开执行机制，任何地址都可以调用，不依赖平台服务器私钥。

核心参数包括：

- 每小时燃烧比例。
- 最短执行间隔。
- 最低池内本币保留数量。
- 是否补算错过的整小时。
- 最大单次燃烧比例。

到达执行时间后，任何用户、机器人或普通转账都可以推动燃烧。

如果启用补算，长时间无人执行时，下一次执行会结算已经过去的完整小时，但燃烧数量不能超过最低保留量限制。

Mint 模式在迁移或募集完成以前不得执行底池燃烧，因为此时正式交易池可能尚未建立。

一键发射和普通部署在 Pair 配置并开盘后才允许燃烧。

## 七、开盘状态机制

开盘是整个发射流程最重要的状态控制。

建议使用明确状态，而不是仅依赖一个时间变量：

- 未配置 Pair。
- 已配置 Pair但未开盘。
- 开盘保护中。
- 正常交易。
- Mint 募集中。
- Mint 已完成并迁移。
- 募集失败并退款。

普通部署由项目方在完成加池后调用开盘。

一键发射由 Factory 在加池和 LP 销毁完成后自动开盘。

Mint 发射由 Vault 在达到募集目标并完成加池后自动开盘。

开盘函数只能成功执行一次，不能重置开盘时间。

## 八、开盘保护机制

推荐参考 DBURN 的分阶段税率，而不是使用含义不清楚的杀区块逻辑。

每个开盘阶段包含持续时间、买入税率和卖出税率。

例如：

- 第一阶段十分钟，买税百分之五，卖税百分之三十。
- 第二阶段十分钟，买税百分之五，卖税百分之二十。
- 第三阶段十分钟，买税百分之五，卖税百分之十。
- 阶段结束后恢复项目设置的正常买卖税。

阶段参数在代币初始化后应保持不可修改，避免项目方开盘后突然提高税率。

开盘前只允许 Factory、Vault、Router 和加池流程需要的地址转账，普通用户交易应当失败。

## 九、平台税机制

平台比例固定占用户设置总交易税的百分之二十。

平台比例由 Factory 内部计算，前端和项目方不能传入或修改。

例如总卖税为百分之五，则平台实际获得交易额的百分之一。

扣除平台份额以后，剩余百分之四再按照项目方选择的分红、回流、燃烧和 fund 比例分配。

平台份额必须独立记账并发送到平台收款地址，不能与项目方 fund 地址混用。

项目方不能通过修改费率、添加 Pair 白名单或更换 TaxProcessor 绕过平台份额。

## 十、项目税费分配

扣除平台税后的剩余部分可以分配到：

- 持币分红。
- 自动回流。
- 交易燃烧。
- 项目 fund。

四项比例合计必须为百分之百。

链上整数计算产生的余数进入项目 fund，确保最终总税始终等于用户设置的买税或卖税。

买税和卖税分别计算，允许项目方设置不同的正常税率。

## 十一、持币分红

项目方可以选择 USDT、WBNB 或其他具有可用流动性路径的代币作为分红币。

分红税由 TaxProcessor 兑换成分红币并存入 DividendDistributor。

达到最低持仓要求的地址按照有效持币比例参与分红。

Pair、Router、Token、Vault、黑洞和分红合约本身不参与分红。

用户可以主动领取，系统也可以在交易过程中自动处理部分地址。

兑换失败时不能清空分红记账，应保留待处理资产并允许后续重试。

## 十二、自动回流

回流税的一部分兑换为交易对资产，另一部分保留为本币，两者重新加入流动性池。

自动回流产生的新 LP 应按照项目规则处理。

为了保持“永久流动性”口径，建议新 LP 同样发送到黑洞，而不是发送给项目方钱包。

如果需要使用 LP Locker，应在前端清楚展示锁定合约和解锁时间，不能同时宣传为永久销毁。

## 十三、交易燃烧

交易燃烧发生在普通买入或卖出扣税过程中。

燃烧份额直接把本币发送到黑洞地址，不参与后续兑换。

交易燃烧减少流通量，底池单边燃烧减少 Pair 的本币储备，两者必须在前端分别展示。

## 十四、交易限制

可选参数包括：

- 单笔最大买入。
- 单笔最大卖出。
- 单钱包最大持仓。
- 普通转账税。
- 分红最低持仓。
- 分红领取间隔。

如果项目计划在开盘后放弃 owner，这些参数必须在创建时确认完整。

如果保留 owner，应限制参数上限，并公开说明项目方可以修改哪些参数。

## 十五、权限设计

Token 的关键经济参数应在初始化后固定，包括：

- 平台比例和平台收款地址。
- 主 Pair。
- 开盘阶段税率。
- 底池燃烧最高比例和最低储备规则。
- TaxProcessor 地址。

项目方可选保留的权限包括：

- 修改项目 fund 地址。
- 调低普通买卖税。
- 调整交易限额。
- 调整分红门槛和领取间隔。

项目方不应拥有以下能力：

- 降低平台份额。
- 将主 Pair 设置为免税。
- 把底池资产提走。
- 修改平台收款地址。
- 在开盘后增加隐藏税收通道。
- 重置开盘时间。

用户可以选择创建后立即放弃 owner，或者保留受限制的项目管理权限。

## 十六、TaxProcessor 机制

TaxProcessor 用于把税收代币兑换为交易对资产，并执行平台、分红、回流和项目 fund 分配。

TaxProcessor 必须为每个 Token 保存独立状态，不能混用不同项目的税收余额。

每次处理时应记录：

- 处理的 Token 数量。
- 获得的交易对资产数量。
- 平台份额。
- 项目 fund 份额。
- 分红份额。
- 回流份额。
- 失败或待重试金额。

如果 TaxProcessor 可升级，平台必须公开升级权限和管理地址。否则即使 Token 已经放弃 owner，税收逻辑仍然存在平台升级风险。

## 十七、靓号部署

Token 使用 CREATE2 部署，前端根据最终构造参数寻找满足后缀要求的 salt。

发行模式属于构造参数的一部分，因此普通部署、一键发射和 Mint 发射必须分别挖盐。

任何影响 Token 初始化参数的字段发生变化后，旧 salt 和旧预测地址立即失效。

链上部署后，Factory 再次检查地址后缀，不符合要求则整笔回滚。

## 十八、源码验证

Factory、Deployer、Token、TaxProcessor、DividendDistributor 和 Mint Vault 都应在 BscScan 完成源码验证。

每次创建项目后，后端根据创建事件自动提交 Token 和 Vault 的源码验证。

前端应展示验证中、验证成功和验证失败状态，并允许失败后重新提交。

## 十九、事件和前端数据

Factory 创建事件应记录：

- 创建者。
- Token 地址。
- Pair 地址。
- Vault 地址。
- 发行模式。
- 总供应量。
- 正常买卖税。
- 平台份额。
- 底池燃烧参数。
- 开盘时间。

底池燃烧、税费兑换、平台收入、项目 fund、分红存入、LP 销毁和开盘都需要独立事件，方便前端和索引服务查询。

## 二十、参考合约差异

SGPRS 模式由 Token 自己创建 Pair，底池燃烧只在卖出时检查，长时间没有卖出就不会执行。

DBURN 模式由外部传入 Pair，底池燃烧为公开函数，可以补算错过的整小时，并设置池内最低保留量。它的开盘阶段税率在初始化后固定，更适合作为新版本参考。

雪球发射台建议采用 DBURN 的 Pair 注入、公开燃烧、最低储备和分阶段开盘思路，同时保留平台占总税百分之二十、持币分红、自动回流和 Mint 发射功能。

## 二十一、最终业务流程

普通部署流程为：用户配置参数，Factory 部署 Token，项目方创建并添加 Pair，Token 确认 Pair，项目方开盘，进入保护阶段，之后进入正常交易。

一键发射流程为：用户配置参数和加池资金，Factory 部署 Token，Factory 创建 Pair并加池，LP 转黑洞，Token 开盘，剩余代币和允许保留的权限交给项目方。

Mint 发射流程为：Factory 部署 Token 和 Vault，用户参与 Mint，Vault 添加或累计流动性，募集完成后锁死 LP，Token 自动开盘并进入保护阶段，Vault 放弃权限。

三种模式开盘后使用相同的正常交易税、平台分账、持币分红、自动回流、交易燃烧和底池单边燃烧机制。
